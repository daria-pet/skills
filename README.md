# Requirements Review Skill

Skill для Claude, який автоматизує структуроване рев'ю вимог (requirements) перед тест-аналізом. Допомагає QA-інженерам, BA та product owner'ам виявляти проблеми у вимогах ще до написання тест-кейсів.

## Навіщо це потрібно

Погано сформульовані вимоги — одна з головних причин переробок у тестуванні: пропущені сценарії, суперечливі тест-кейси, нескінченні уточнення в процесі роботи. Цей skill формалізує процес рев'ю вимог так, щоб проблеми виявлялися systematically, а не «на око».

## Що робить skill

За запитом користувача (наприклад, «перевір цю вимогу» або «чи готова ця вимога до тест-аналізу») Claude:

1. Читає вимогу повністю (і суміжні вимоги, якщо надані — для перевірки на дублювання й суперечності).
2. Перевіряє її за **7 критеріями якості**:
   - **Атомарність** — вимога описує рівно одну поведінку.
   - **Однозначність** — відсутні розмиті формулювання без чітких критеріїв.
   - **Повнота** — описані негативні сценарії та межові умови.
   - **Несуперечність** — немає внутрішніх або міжвимогових конфліктів.
   - **Неповторюваність** — вимога не дублює інші надані вимоги.
   - **Тестованість** — для кожного твердження можна сформулювати перевірку.
   - **Реалізовність** — вимога не суперечить очевидним технічним обмеженням.
3. Формує звіт: вердикт, таблицю знахідок (критерій, цитата, проблема, severity, пропозиція виправлення), список питань до BA та короткий підсумок.

## Приклад тригерів

- «Перевір цю вимогу»
- «Зроби рев'ю вимог»
- «Чи готова ця вимога до тестування?»
- «Чи можна писати тест-кейси по цій вимозі?»

Якщо текст вимоги не надано, Claude попросить його надати перед аналізом.

## Формат результату

```
Ревʼю вимоги
1. Вердикт: Готова до тест-аналізу / Потребує уточнень / Не готова
2. Знахідки за критеріями (таблиця, включно з критеріями без порушень)
3. Питання до BA
4. Короткий підсумок
```

Severity знахідок:
- **Critical** — блокує тест-аналіз (неможливо зрозуміти очікувану поведінку).
- **Major** — ризик пропущених сценаріїв або суперечливих тестів.
- **Minor** — неточність, що не блокує аналіз.

Вимога вважається неготовою до тест-аналізу, якщо знайдено більше двох Critical-знахідок.

## Ключові принципи

- Кожна знахідка спирається на дослівну цитату з тексту вимоги — жодних вигаданих проблем.
- Прогалини в інформації формулюються як питання до BA, а не як звинувачення чи факти.
- Skill не пом'якшує і не перебільшує результати — лише те, що підтверджено текстом.
- Обов'язково відзначаються сильні сторони вимоги, а не лише проблеми.

## Встановлення

Помістіть `SKILL.md` у теку skill'ів вашого проєкту (наприклад, `/mnt/skills/plugins/requirements-review/SKILL.md` або відповідний шлях у вашому середовищі Claude). Claude автоматично підхопить skill за описом і триггерними фразами.
